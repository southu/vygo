# TESTLOG — vygo-production-campaign-verification, iteration 1

Production-focused verification and remediation of the three deployed Vygo
campaign landing pages. The three campaign routes are defined by the application
configuration (`apps/web/src/content/campaigns/*`) and exposed in the crawlable
sitemap (`apps/web/src/app/sitemap.ts`). Their exact live production URLs:

1. `https://www.vygo.ai/ai-workforce-capability-assessment` — AI production-readiness
   assessment (primary conversion: the existing `/readiness` assessment-start flow).
2. `https://www.vygo.ai/learning-development-leaders` — scalable learning support
   for L&D / enablement leaders (primary conversion: on-page waitlist application).
3. `https://www.vygo.ai/leaders/workforce-capability` — workforce capability &
   builder engagement for engineering leaders (primary conversion: on-page waitlist).

## Live baseline (pre-change)

- `GET https://www.vygo.ai/version` → `7a847bdb0e25af40f59ffa3d92088ebd3dd1b755`,
  matching `origin/main` HEAD when this baseline was recorded.
- All three campaign URLs return HTTPS `200` (no redirect loop):
  `/ai-workforce-capability-assessment 200`, `/learning-development-leaders 200`,
  `/leaders/workforce-capability 200`.
- `GET /robots.txt` → `200`; contains no `Disallow`/`noindex` for the campaign
  paths. `GET /sitemap.xml` → `200` and lists all three campaign canonicals.
- Each page declares `robots: { index: true, follow: true }`, a unique absolute
  canonical matching its production URL, and unique title/description.

## Defect found and remediated

**Missing Twitter/X card image alt text on the assessment landing page.**
`apps/web/src/app/ai-workforce-capability-assessment/page.tsx` emitted its
`twitter:image` as a bare URL string (`images: [meta.ogImage]`), so no
`twitter:image:alt` tag was produced — the social-card image would be announced
without a description. The other two campaign pages (fixed in commit `204bdb4`)
already carry the alt text. This page still had the `meta.ogImageAlt` value
(`"vygo.ai"`) available but unused.

Fix: pass the image as `{ url: meta.ogImage, alt: meta.ogImageAlt }`, matching
the established pattern. Confirmed in the exported HTML:
`<meta name="twitter:image:alt" content="vygo.ai"/>` (parity with the existing
`<meta property="og:image:alt" content="vygo.ai"/>`). All three campaign pages
now emit a non-empty `twitter:image:alt`.

Regression lock: `apps/web/e2e/campaign-assessment.spec.ts` now asserts the
assessment page renders exactly one `twitter:image:alt`, that it is non-empty,
and that `og:image:alt` is present.

# TESTLOG — vygo-qa-uat-verification-pass, iteration 1

Full verification-and-evidence pass against the deployed site
`https://www.vygo.ai`, validating the four shipped QA & UAT content blocks:
(a) the Team/About **QA & UAT Lead** card (`/careers`), (b) the How-We-Work
**QA step** (`/method`), (c) the engagement-tier **deliverables bullets**
(`/pricing`, every tier), and (d) the **QA/UAT FAQ** entry (homepage).

This is a verification mission. Live content already matched the repository and
passed every acceptance criterion, so **no site content was changed**. The only
repository change is a new e2e content-lock spec plus captured evidence
artifacts. `version.txt` / the version endpoint are untouched.

## Change applied this iteration

Added `apps/web/e2e/qa-uat-copy.spec.ts` — a Playwright content-lock spec (5
tests) that asserts, against the rendered DOM:

1. `/careers` renders the QA & UAT Lead card with its approved summary and no
   workforce-location / optional-framing terms.
2. `/method` renders the QA step including its decision-gate phrase
   `not just developer-tested code`.
3. `/pricing` shows **both** QA/UAT bullets **exactly once in every tier**
   (`launch`, `scale`, `enterprise`).
4. The homepage FAQ expands to the QA/UAT answer containing
   `separate from the engineers writing the code`.
5. Both verbatim phrases survive in production content.

`pnpm typecheck`, `eslint`, and `prettier --check` pass on the new spec. The
spec passes against the live site (`5 passed`) and runs in CI against a local
build via the default Playwright `baseURL`.
